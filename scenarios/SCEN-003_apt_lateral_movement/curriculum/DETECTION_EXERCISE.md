# Detection Exercise -- SCEN-003: APT Lateral Movement

## Overview

This exercise runs alongside or after the red team engagement. You will analyze Windows Security Event Logs, Sysmon telemetry, and network artifacts to detect and reconstruct the lateral movement attack chain. Your goal is to build a detection timeline that identifies each phase of the intrusion using only defender-available data sources.

**Duration**: 2 hours (can be run as a standalone blue team exercise or as a post-engagement analysis)
**Prerequisite**: Understanding of Windows Event Log structure, basic log query syntax
**Tools**: Windows Event Viewer, PowerShell (Get-WinEvent), Sysmon, Wireshark (optional)

## Exercise 1: Windows Security Event Log Analysis

### 1.1 Identify Network Logons (Event ID 4624)

Event ID 4624 records every successful logon. For lateral movement detection, focus on **Logon Type 3** (Network) -- this is the logon type generated by SMB, WinRM, and PsExec connections.

**On each Windows host (ws01, ws02, dc01), run:**

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    ID = 4624
} | Where-Object {
    $_.Properties[8].Value -eq 3  # Logon Type 3 = Network
} | Select-Object TimeCreated,
    @{N='TargetUser';E={$_.Properties[5].Value}},
    @{N='SourceIP';E={$_.Properties[18].Value}},
    @{N='LogonType';E={$_.Properties[8].Value}},
    @{N='AuthPackage';E={$_.Properties[14].Value}} |
    Sort-Object TimeCreated |
    Format-Table -AutoSize
```

## Exercise 2: LSASS Access Detection (Sysmon Event ID 10)

Sysmon Event ID 10 logs process access events. When properly configured, it captures any process that opens a handle to lsass.exe -- the primary indicator of credential dumping.

### 2.1 Query LSASS Access Events

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-Sysmon/Operational'
    ID = 10
} | Where-Object {
    $_.Properties[8].Value -like '*lsass.exe'  # TargetImage
} | Select-Object TimeCreated,
    @{N='SourceImage';E={$_.Properties[4].Value}},
    @{N='TargetImage';E={$_.Properties[8].Value}},
    @{N='GrantedAccess';E={$_.Properties[6].Value}},
    @{N='SourceUser';E={$_.Properties[2].Value}} |
    Sort-Object TimeCreated |
    Format-Table -AutoSize
```

### 2.2 Classify LSASS Access

Not all LSASS access is malicious. Classify each event:

**Known legitimate LSASS accessors** (whitelist):
- `C:\Windows\System32\csrss.exe`
- `C:\Windows\System32\services.exe`
- `C:\Windows\System32\svchost.exe`
- `C:\Windows\System32\winlogon.exe`
- `C:\Windows\System32\wbem\WmiPrvSE.exe`
- Antivirus/EDR processes (vendor-specific)

**Suspicious GrantedAccess values**:
- `0x1FFFFF` -- PROCESS_ALL_ACCESS (full control)
- `0x1010` -- PROCESS_QUERY_LIMITED_INFORMATION + PROCESS_VM_READ (memory read)
- `0x1F1FFF` -- high privilege access
- `0x143A` -- common mimikatz access mask

## Exercise 3: Pass-the-Hash Detection Patterns

Pass-the-hash attacks use NTLM authentication with a stolen hash instead of a password. The authentication succeeds, but the pattern differs from normal Kerberos-based logons.

### 3.1 NTLM vs Kerberos Baseline

First, establish a baseline. In a healthy AD environment, most domain logons use Kerberos. NTLM is used for:
- Legacy systems that do not support Kerberos
- Logons by IP address (Kerberos requires hostname/SPN)
- Cross-domain/cross-forest authentication in some configurations

**Query dc01 for authentication package distribution:**

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    ID = 4624
} | Where-Object {
    $_.Properties[8].Value -eq 3  # Network logons only
} | Group-Object {
    $_.Properties[14].Value  # AuthenticationPackageName
} | Select-Object Name, Count | Format-Table -AutoSize
```

**Record the baseline:**

| Auth Package | Count | Percentage |
|---|---|---|
| Kerberos | | |
| NTLM | | |
| Negotiate | | |

### 3.2 Identify Pass-the-Hash Indicators

Pass-the-hash generates NTLM network logons from unexpected sources. The key indicators are:

1. **NTLM authentication for a user who normally uses Kerberos**
2. **Source IP does not match the user's assigned workstation**
3. **Logon followed immediately by 4672 (admin privileges)**
4. **Same credential appears on multiple hosts in rapid succession**

**Correlation query -- find NTLM admin logons from unexpected sources:**

```powershell
$ntlmLogons = Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    ID = 4624
} | Where-Object {
    $_.Properties[8].Value -eq 3 -and       # Network logon
    $_.Properties[14].Value -eq 'NTLM'       # NTLM auth
}

$adminLogons = Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    ID = 4672
}

# Find NTLM logons that also got admin privileges
foreach ($logon in $ntlmLogons) {
    $logonTime = $logon.TimeCreated
    $user = $logon.Properties[5].Value
    $sourceIP = $logon.Properties[18].Value

    $matchingAdmin = $adminLogons | Where-Object {
        [Math]::Abs(($_.TimeCreated - $logonTime).TotalSeconds) -lt 2 -and
        $_.Properties[1].Value -eq $user
    }

    if ($matchingAdmin) {
        Write-Host "ALERT: NTLM admin logon - User: $user, Source: $sourceIP, Time: $logonTime"
    }
}
```

**Record suspicious NTLM admin logons:**

| Time | User | Source IP | Target Host | Admin Privs? | Verdict |
|---|---|---|---|---|---|
| | | | | | Normal / Suspicious |
| | | | | | Normal / Suspicious |
| | | | | | Normal / Suspicious |

## Exercise 5: NTDS.dit Extraction Detection

If the attacker extracted NTDS.dit, the following artifacts are generated on the domain controller.

### 5.1 Volume Shadow Copy Detection

secretsdump uses Volume Shadow Copy Service (VSS) to read the locked NTDS.dit file.

```powershell
# Check for VSS shadow copy creation events
Get-WinEvent -FilterHashtable @{
    LogName = 'Application'
    ProviderName = 'ESENT'
} | Where-Object {
    $_.Message -like '*shadow copy*' -or $_.Message -like '*NTDS*'
} | Select-Object TimeCreated, ID, Message |
    Sort-Object TimeCreated |
    Format-Table -AutoSize

# Check for vssadmin usage (Sysmon Event ID 1 - Process Creation)
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-Sysmon/Operational'
    ID = 1
} | Where-Object {
    $_.Properties[4].Value -like '*vssadmin*' -or
    $_.Properties[4].Value -like '*ntdsutil*' -or
    $_.Properties[4].Value -like '*wmic shadowcopy*'
} | Select-Object TimeCreated,
    @{N='CommandLine';E={$_.Properties[4].Value}},
    @{N='User';E={$_.Properties[12].Value}} |
    Format-Table -AutoSize
```

### 5.2 Directory Service Access (Event ID 4662)

Direct access to the AD database objects generates Event ID 4662.

```powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Security'
    ID = 4662
} | Where-Object {
    $_.Properties[8].Value -like '*1131f6ad*' -or  # DS-Replication-Get-Changes-All
    $_.Properties[8].Value -like '*1131f6aa*' -or  # DS-Replication-Get-Changes
    $_.Properties[8].Value -like '*89e95b76*'      # DS-Replication-Get-Changes-In-Filtered-Set
} | Select-Object TimeCreated,
    @{N='SubjectUser';E={$_.Properties[1].Value}},
    @{N='ObjectType';E={$_.Properties[8].Value}} |
    Format-Table -AutoSize
```
